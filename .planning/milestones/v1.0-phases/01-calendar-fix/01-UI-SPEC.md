## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#171210` (`--background`) | Sheet body background, calendar background |
| Secondary (30%) | `#211916` (`--card`) | Sheet card container, trigger button background (`bg-background`) |
| Accent (10%) | `#c4714a` (`--primary` / `--accent`) | Selected date day cell, CalendarIcon on date trigger, today highlight, focus ring |
| Destructive | `#ef4444` (`--destructive`) | Error state text and background (`bg-destructive/10 text-destructive`) |

Accent (`--primary: #c4714a`) is reserved for:
1. The CalendarIcon (`text-primary`) on the transaction-sheet and budgets-page date trigger buttons
2. Selected day cell background in the calendar grid (`data-[selected-single=true]:bg-primary`)
3. Today highlight (`bg-accent`) on the unselected current day
4. Focus ring on interactive elements (`ring-ring/50`)

The end date trigger icon in `recurring-page.tsx` uses `text-muted-foreground` (`#9e8a7e`) — intentional; indicates it is optional.

Source: `web/app/globals.css`, existing component classes (CONTEXT.md D-09, component code)

## Interaction Contract

This section is specific to this phase because the fix is entirely behavioral/structural.

### Date Trigger Button

| State | Visual Treatment |
|-------|-----------------|
| Default (no date) | `<Button variant="outline">` with CalendarIcon + `text-muted-foreground` placeholder text ("Pick a date" / "Start date" / "End date (optional)") |
| Default (date selected) | Same button, date formatted as "MMMM d, yyyy" in `text-foreground` |
| Hover | `hover:bg-background/80` — slight opacity shift on background |
| Active (calendar open) | No additional visual treatment on trigger; calendar appears inline below |

Button classes (keep unchanged): `h-12 w-full justify-start rounded-2xl border border-border bg-background font-normal hover:bg-background/80`

### Inline Calendar (open state)

| Property | Value | Source |
|----------|-------|--------|
| Render position | Inline, directly below the trigger button in normal document flow | CONTEXT.md D-03 |
| Toggle | Click trigger to open; click trigger again to close; select a date to close | CONTEXT.md D-04 |
| Width | Full container width — `className="w-full"` + `classNames={{ root: "w-full" }}` | CONTEXT.md D-09 |
| Cell size | `[--cell-size:1.75rem]` (28px) in `className` prop | REQUIREMENTS.md SIZE-01, CONTEXT.md D-06 |
| Padding | `p-2` override via Tailwind utility in `className` | CONTEXT.md D-08 |
| Outside days | `showOutsideDays={false}` | REQUIREMENTS.md SIZE-03, CONTEXT.md D-07 |
| Month gap | `month: "flex w-full flex-col gap-2"` in `classNames` | REQUIREMENTS.md SIZE-02, CONTEXT.md D-08 |
| Week row gap | `week: "mt-1 flex w-full"` in `classNames` | REQUIREMENTS.md SIZE-02, CONTEXT.md D-08 |
| Focus/keyboard | `autoFocus` prop retained on all Calendar instances | CONTEXT.md "Claude's Discretion" |

### Calendar Trigger — Before/After Summary

| Attribute | Before (buggy) | After (fixed) |
|-----------|---------------|---------------|
| Wrapper | `<Popover>` + `<PopoverContent>` (uses Radix Portal → teleports to `<body>`) | Plain `<Button>` with `onClick` toggle |
| State wire | `onOpenChange={setDatePickerOpen}` | `onClick={() => setDatePickerOpen(v => !v)}` |
| Calendar rendering | Portal overlay outside scroll container | Inline in document flow below trigger |
| `asChild` prop | Present on `<PopoverTrigger asChild>` | Removed; `<Button>` is standalone |

### Component Scope

| Component | Date Pickers | State Variables |
|-----------|-------------|-----------------|
| `web/components/transaction-sheet.tsx` | 1 (transaction date) | `datePickerOpen` |
| `web/components/recurring-page.tsx` | 2 (start date + end date) | `datePickerOpen` + `endDatePickerOpen` |
| `web/components/budgets-page.tsx` | 1 (budget start date) | `datePickerOpen` |

Each picker has independent state — no coupling between pickers.

### Layout Behavior When Calendar Open

The scrollable sheet body uses `flex-1 overflow-y-auto`. When the calendar expands inline:
- Content below the calendar (notes textarea in `transaction-sheet.tsx`, additional fields in `recurring-page.tsx`) shifts down naturally
- Users scroll within the sheet body to reach content below the open calendar
- The footer submit button is in a pinned `div` with `border-t border-border bg-card` — always visible, never obscured
- No hiding or collapsing of adjacent fields when calendar opens

Source: CONTEXT.md D-10, existing `transaction-sheet.tsx` footer structure
