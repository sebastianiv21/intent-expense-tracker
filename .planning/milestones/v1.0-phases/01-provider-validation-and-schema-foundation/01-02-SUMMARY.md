## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] drizzle-kit push blocked by NOT NULL without runtime default**

- **Found during:** Task 2
- **Issue:** `drizzle-kit push` detected 17 existing rows would violate `original_amount NOT NULL` because drizzle-kit push applies schema state directly (not the .sql file). It prompted for table truncation confirmation.
- **Fix:** Added `DEFAULT '0'` to the `original_amount` ADD COLUMN statement in the .sql migration file so existing rows receive 0 before the UPDATE backfill sets the real values.
- **Files modified:** web/drizzle/0003_multi-currency-schema.sql
- **Commit:** eb5919c (included in Task 1 commit)

**2. [Rule 3 - Blocking] drizzle-kit migrate tried to replay already-applied migrations**

- **Found during:** Task 2
- **Issue:** `drizzle-kit migrate` failed on `0002_add-currency-to-financial-profile` with `column "currency" already exists` — the live database has no `__drizzle_migrations` tracking table (prior migrations were applied via `drizzle-kit push`, which doesn't create the migrations journal table). So `migrate` tried to replay 0000, 0001, 0002 all of which were already applied.
- **Fix:** Applied the migration SQL statements directly via the `@neondatabase/serverless` neon connection in a Node.js script. This executes exactly the same SQL as the migration file in order, without the replay problem.
- **Files modified:** none (DB-only change)
- **Commit:** n/a (no file changes for Task 2)
