<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer → Neon database | Migration push is a developer operation; no user-facing input crosses this boundary |
| migration SQL → live data | The UPDATE backfill modifies existing rows — potential for data loss if SQL is incorrect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | web/drizzle/0003_multi-currency-schema.sql | mitigate | Generated by drizzle-kit (not hand-written); only the UPDATE backfill line is manually added. Executor must read the file before pushing to confirm correctness. |
| T-02-02 | Tampering | Neon DB — existing transaction rows | mitigate | `UPDATE transactions SET original_amount = amount` is a safe copy; the original `amount` column is NOT modified. `exchange_rate` DEFAULT '1.0' and `currency` DEFAULT 'USD' are semantically correct for all existing USD rows. |
| T-02-03 | Denial of Service | drizzle-kit push | accept | If push fails, database is unchanged (DDL is transactional in PostgreSQL). Executor should surface errors to user rather than retry. |

Note: This phase involves only DDL migrations and data backfill run by the developer. No authentication, authorization, or user-facing input is involved. ASVS L1 categories not applicable.
</threat_model>
