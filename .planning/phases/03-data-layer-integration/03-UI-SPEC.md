## Component Inventory

### Currency Badge (new)

Replaces the hardcoded `<span>$</span>` at line 299-305 in `transaction-sheet.tsx`.

```
[USD]   ← tappable badge, opens currency popover
```

Anatomy:
- Outer: `<PopoverTrigger asChild>`
- Inner: `<button>` — 44px min-height, `rounded-xl`, `border border-border`, `bg-muted`,
  `px-3 py-2`, font-mono, 14px bold
- Content: currency code text only (e.g. `USD`, `COP`) — no symbol, no icon
- Active (popover open): `border-primary`, `bg-primary/10`, `text-primary`
- Inactive: `border-border`, `bg-muted`, `text-muted-foreground` — shifts to foreground
  color on hover

Sizing: badge sits flush left of the amount input within the same `flex items-center
justify-center` row. Amount input keeps `flex-1`.

### Currency Popover (new)

Opens below the currency badge. Contains exactly two option buttons: `USD` and `COP`.

```
┌──────────────┐
│  ● USD       │
│  ○ COP       │
└──────────────┘
```

- Container: `PopoverContent` with `w-32 p-1` — same compact style as date picker popover
- Each option: full-width button, `h-11` (44px), `rounded-lg`, `text-sm font-bold`,
  `text-left px-3`
- Selected currency: `bg-primary/10 text-primary font-bold`
- Unselected: `text-foreground hover:bg-muted`
- No search, no scroll — exactly two options (USD and COP)
- Closes on selection

### Conversion Preview Row (new)

Displayed below the amount input area, above the type toggle. Only rendered when:
- The selected currency differs from the user's base currency, AND
- The user has entered an amount > 0

```
≈ $12.50 USD
```

Layout: centered text, `text-sm text-muted-foreground tabular-nums`, `mt-2 mb-0`.
Loading state: `"Fetching rate…"` in `text-muted-foreground/50` (dimmed).
Error state: hidden — full error surfaces in the `<p role="alert">` block instead.

When `currency === baseCurrency`: preview row is not rendered (no conversion needed).

### Amount Input (modified)

- `inputMode` switches based on currency:
  - COP: `inputMode="numeric"` (no decimal keyboard on mobile)
  - USD: `inputMode="decimal"` (existing)
- `placeholder`:
  - COP: `"0"` (no decimal places shown)
  - USD: `"0.00"` (existing)
- Formatting via extended `formatAmountDisplay` / `parseAmountInput` — COP strips all
  decimal input, USD preserves up to 2 decimal places

## Interaction Contract

### Currency Selection Flow

1. User taps currency badge → popover opens immediately (no animation delay)
2. User selects a currency → popover closes, badge text updates to new currency code
3. If user selects a currency different from base: conversion preview appears below amount
4. If user selects base currency: conversion preview disappears
5. Currency resets to base currency on each new form open (CONTEXT.md D-03)

### Conversion Preview Trigger

Preferred approach (from CONTEXT.md discretion — "keep it simple"):
- Rate is fetched **once on currency selection** (not debounced per keystroke)
- Preview updates **on amount blur** (when user leaves the amount field) using the
  already-fetched rate for client-side multiplication — no second network call
- Loading state shown during the initial rate fetch on currency selection
- If the rate fetch fails: preview stays hidden, error appears in the alert block

Rationale: avoids per-keystroke server calls, respects the 1,500 req/month API budget.

### Edit Mode Pre-fill

When opening an existing COP transaction for edit:
- Amount field pre-filled with `originalAmount` (the COP value the user entered)
- Currency badge shows `COP` (from `transaction.currency`)
- Conversion preview rendered immediately using stored `exchangeRate` × `originalAmount`
  (no new API call on open — only re-fetches if user changes currency or date)

### Amount Formatting per Currency

| Currency | Decimal places | inputMode | placeholder | Formatter behavior |
|----------|---------------|-----------|-------------|-------------------|
| USD | 2 | `decimal` | `0.00` | Existing parseAmountInput / formatAmountDisplay |
| COP | 0 | `numeric` | `0` | Strip decimal input; format as integer with thousand separators |

COP thousand separator: comma (e.g. `50,000`) — consistent with `en-US` locale already
used in `formatAmountDisplay`.

### Accessibility

- Currency badge: `aria-label="Select currency"` + `aria-expanded` (managed by Popover)
- Currency popover options: `role="option"` or `aria-pressed` on each button
- Conversion preview: `aria-live="polite"` so screen readers announce the updated amount
- Rate fetch error: `role="alert"` (existing pattern)
- All tap targets: minimum 44px height (WCAG 2.5.5 AAA target size)
