<threat_model>
## Trust Boundaries

This plan modifies client-side display logic only. No new user inputs are accepted, no server actions are called, no authentication is involved.

| Boundary | Description |
|----------|-------------|
| Data → display | `transaction.exchangeRate` is a Drizzle-returned string from a value written by Phase 3 server actions. The display math (`Math.round(1 / parseFloat(exchangeRate))`) is read-only — no value is written back. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Tampering | `invertedRate` computation | accept | `parseFloat(transaction.exchangeRate)` is read-only display math. Division-by-zero is guarded by `invertedRate !== null` check before render — if rate parses to 0 or NaN, detail row is suppressed rather than showing "Infinity". |
| T-04-02-02 | Information Disclosure | Expanded detail row | accept | The detail row displays data the user already entered (their own transaction data within an authenticated session). No additional PII exposure. |
| T-04-02-03 | Denial of Service | `useState` per TransactionItem | accept | One boolean per list item. With 100 items rendered, this is 100 booleans — negligible memory. No unbounded growth. |

Security enforcement notes: This plan introduces zero new trust boundaries, no new user inputs, and no server calls. All upstream controls (auth, validation, rate fetching) are established in Phases 1–3. ASVS L1 categories V2–V6 are unaffected.
</threat_model>
