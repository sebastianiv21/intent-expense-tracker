<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Client-side currency spoofing (attacker modifies form payload to send currency="COP" with baseCurrency="COP" to avoid rate fetch, storing wrong amount) | HIGH | Both `currency` and `baseCurrency` are validated as `z.enum(["USD", "COP"])` in the Zod schema in the server action (Plan 01). Even if the client sends mismatched values, the server recomputes the rate using `getOrFetchExchangeRate(currency, baseCurrency, date)` — the server is the source of truth for the conversion math. |
| Preview rate manipulation (client-side `previewRate` state is modified by an attacker via browser devtools to show a misleading preview) | LOW | The preview is display-only — it is never sent to the server. The server action independently calls `getOrFetchExchangeRate` on save. A manipulated preview cannot affect the stored amount. |
| Amount formatting bypass (attacker sends a decimal COP amount e.g. "500.50" bypassing the client-side decimal strip) | MED | The server action receives a `z.coerce.number()` amount — "500.50" parses to 500.50. The server does not strip COP decimals; it uses whatever number is sent. The amount field strips decimals client-side (onChange guard), and `inputMode="numeric"` removes the decimal key on mobile. For a hardened implementation, the server action could round to `getCurrencyDecimals(currency)` places — acceptable risk for a single-user personal app; noted for future hardening. |
| Rate fetch failure silently unblocking save (error state cleared before user sees it) | LOW | `setError` is called inside `handleCurrencySelect` on failure; the error is only cleared by `setError(null)` at the top of the next `handleSubmit` call. The save button does not auto-clear the error. The user must explicitly retry. |
| Stale previewRate used for a different date (user selects COP, fetches rate for today, then changes date in the date picker without re-fetching) | MED | Acceptable UX tradeoff per CONTEXT.md discretion ("keep it simple — rate fetched once on currency selection"). The preview is an approximation ("≈") — the exact rate is always fetched fresh by the server action on save using the submitted date. The preview label uses "≈" to communicate approximation. |
